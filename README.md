# movie-web

SvelteKit + TypeScript frontend for the movie catalogue. It lets you browse, search, create, edit and delete **movies** (with artwork upload) and **cast & crew**, and link people to movies as credits.

It talks to the backend in two ways:

- **GraphQL** (`POST /graphql`) for all data, through the **Apollo Router**, which combines `movie-service` and `people-service` into one API. It uses [urql](https://commerce.nearform.com/open-source/urql/) with types generated by [GraphQL Code Generator](https://the-guild.dev/graphql/codegen).
- **REST** (`POST /movies/{id}/artwork`) for artwork uploads, straight to `movie-service`, with a progress bar and cancel

The app doesn't know which service answers which field. A query like `movie { credits { person { name } } }` is split by the router between the two services.

## Features

- Movies grid with artwork, skeleton loaders, and empty and error states
- Movie detail page with cast & crew; add and remove credits (roles limited to the person's roles)
- Create and edit movies and people with inline validation; delete with a confirmation dialog
- Artwork upload: click or drag and drop, preview, progress bar, cancel, type and size checks (JPEG/PNG/WebP, max 5 MB)
- People page with role tabs (`/people?role=DIRECTOR`)
- Debounced search on the Movies and People pages, with a loading indicator
- Toast notifications and a responsive layout from phone to desktop

## Prerequisites

- **Node.js 22.23.4** (pinned in `.tool-versions`; with [asdf](https://asdf-vm.com/): `asdf install`)
- **Apollo Router** running on `http://localhost:4000`
- **movie-service** running on `http://localhost:8080`
- **people-service** running on `http://localhost:8081`

See the umbrella repo's README for how to start them.

## Getting started

```bash
npm install
npm run dev
```

Open http://localhost:5173. It redirects to `/movies`.

In development, Vite proxies requests (see `vite.config.ts`), so the browser only talks to its own origin and no CORS setup is needed:

| Path | Proxied to |
|---|---|
| `/graphql` | Apollo Router, `http://localhost:4000` |
| `/movies/{id}/artwork` | movie-service, `http://localhost:8080` |

## GraphQL types (codegen)

Queries and mutations live in `src/lib/graphql/*.ts`, written with the `graphql()` helper. `npm run codegen` reads the combined schema from the running router (`http://localhost:4000/graphql`) and writes typed documents and types to `src/lib/graphql/generated/`.

Run it after changing a query or when the backend schema changes. For a backend change, recompose the router's supergraph first (see the umbrella README), because codegen sees whatever schema the router is serving. The generated folder is committed, so `npm run check`, `npm run dev` and `npm test` work without running codegen first.

## Running the tests

Tests use [Vitest](https://vitest.dev/) with two projects (configured in `vite.config.ts`):

| Files | Runs in | For |
|---|---|---|
| `*.spec.ts` | Node | plain TypeScript (e.g. `src/lib/api/artwork.spec.ts`) |
| `*.svelte.spec.ts` | headless Chromium (Vitest browser mode + Playwright) | Svelte components |

Test files sit next to the code they test.

```bash
npm install
npm run test:setup   # once per machine (and again after upgrading Playwright)
npm test
```

`npm run test:setup` downloads Chromium into Playwright's shared cache (`~/Library/Caches/ms-playwright` on macOS, `~/.cache/ms-playwright` on Linux), not into the project. Without it, the Node tests still run, but component tests fail with `browserType.launch: Executable doesn't exist`.

The tests don't need the backend running.

## Project structure

```
src/
├── lib/
│   ├── api/          REST helpers (artwork upload)
│   ├── components/   reusable UI (MovieCard, MovieForm, PersonForm, SearchInput, ConfirmDialog, Toaster, ...)
│   ├── graphql/      queries and mutations; generated/ holds codegen output
│   ├── model/        label maps for enums (genres, roles)
│   └── state/        shared app state (toasts)
└── routes/
    ├── movies/       list, /new, /[id] detail (layout loads the movie once), /[id]/edit
    └── people/       list with role tabs, /new, /[id]/edit
```
